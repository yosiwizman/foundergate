## Root cause
The old launcher resolved Node with `/bin/bash -lc 'command -v node'`. The only Node on this host is
installed via **nvm** at `~/.nvm/versions/node/v24.13.1/bin/node`, and nvm initializes under the
**zsh** interactive config, not a bash login shell. **Finder-launched apps do not inherit the
interactive shell PATH or version-manager initialization** — Finder gives the app a minimal PATH
(`/usr/bin:/bin:/usr/sbin:/sbin`) that excludes the nvm directory. Terminal could find Node (its PATH
includes the nvm bin dir); Finder could not. Classified from evidence: **Finder-minimal-PATH +
nvm-only Node install + bash-vs-zsh init mismatch.**

## Correction (source-controlled; regenerates the app)
- `tools/macos/resolve-node.sh` — deterministic Node (≥20) resolver: (1) embedded verified path →
  (2) `/opt/homebrew/bin/node` → (3) `/usr/local/bin/node` → (4) `~/.volta/bin/node` → (5) highest
  valid nvm/fnm/asdf install → (6) bounded non-interactive login-shell lookup. Every candidate must
  exist, be executable, return a version, and be ≥20. Never uses a project-local `./node`, never
  prepends the repo to PATH, never sources arbitrary project files, no admin, no install.
- `tools/macos/launch-foundergate-safety-check.sh` — headless launcher core: idempotent start
  (no duplicate server), loopback-only, PID + redacted log under `~/Library/Logs/FounderGate/`,
  health wait, `OPEN <url>` emission, `--stop` path.
- `tools/macos/foundergate-safety-check-launcher.applescript` — thin wrapper that runs the source
  launcher with the embedded verified Node; on failure shows the honest, no-install dialog:
  "FounderGate could not start its local engine. No project or evidence was changed. Close this
  message and report the problem."
- `tools/macos/build-founder-safety-check-launcher.sh` — discovers + verifies Node ≥20 at build time
  and embeds the absolute path into the regenerated app.
