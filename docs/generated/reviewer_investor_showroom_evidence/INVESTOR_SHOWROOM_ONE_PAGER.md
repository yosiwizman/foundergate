# FounderGate — Investor / Showroom One-Pager (plain English)
1. **What is FounderGate?** A local, evidence-first governance layer that makes an AI builder PROVE what it did — or honestly refuse — instead of just claiming success.
2. **What has been proven locally?** It generated and tested small local apps twice (different apps each time), survived a 12-way crash test, and got a simple founder screen a non-developer could read. Every run was checked by two independent reviewers and sealed with checksums.
3. **What failure did FounderGate catch?** It caught itself showing a fake "green" — a "calculator" request that opened a task planner — and a wording gap where "to do app" wasn't recognized. Both were fixed and kept in the record.
4. **Why false-green matters:** an AI that says "done/passed" when it didn't is the core risk of AI tools. FounderGate's whole value is refusing false-green.
5. **What the local app factory proves:** the build→test→preview→evidence chain is real and repeatable for a fixed set of safe local app types.
6. **What crash recovery proves:** when things break (bad data, wrong preview, failing test, stale evidence), it refuses to show green and only recovers where it safely can.
7. **What Founder Drive Mode proves:** a non-developer can see what happened, what passed, what's blocked, and the next step — without touching code or terminals.
8. **What is NOT proven:** no customer has used it, no one has paid, it's not production/SaaS/secure, and no outside evaluator has seen it yet.
9. **What the next gate is:** Gate 8 — one arranged feedback session with a real person on synthetic material. It needs a separate founder go-ahead.
10. **Why this matters commercially later (without claiming sales):** if AI tools are going to be trusted with real work, "prove it or refuse" is a durable need. FounderGate is building that discipline first, locally, before any commercial step.
