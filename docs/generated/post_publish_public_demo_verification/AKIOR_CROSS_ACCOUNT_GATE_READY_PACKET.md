# AKIOR Cross-Account Gate — Ready Packet (Preparation Only)
## Purpose
Prove that the same clean, honest, self-verifying demo discipline works across a SECOND, independent account (AKIOR) — a technical/portability proof.

## What would count as cross-account proof
- A separate public (or account-scoped) repo created under the AKIOR account containing a vetted, synthetic-data demo.
- A fresh clone from that account's URL passing its self-test green, with the same clean scans (secrets 0, internal-refs 0, overclaims 0).
- Evidence that the two accounts are genuinely distinct (different owner), and that no private data crossed between them.

## What it would NOT prove
- Nothing about production readiness, security, compliance, customers, revenue, provider integration, or deployment.
- It is a portability/discipline proof only.

## Repo / account requirements
- Must be the founder's own AKIOR account (or an account the founder legitimately controls).
- New repo, synthetic data only, honest limitations, MIT (or chosen OSS) license, no secrets.

## No-private-data rule
- Synthetic/sample data only. No customer, personal, production, or proprietary content. No credentials.

## Expected evidence package (when later authorized)
- AKIOR_OUTSIDE_IN_VERIFICATION.md, AKIOR_CLONE_SELFTEST_REPORT.md, AKIOR secret/internal-ref/claim/network scans, AKIOR_PROOF_INDEX.md, cross-account distinctness evidence, prohibited-action attestation, one sealed ZIP.

## Explicit non-authorization
- This packet does NOT authorize creating the AKIOR repo, logging into AKIOR, or any external AKIOR action. It only defines the gate.
