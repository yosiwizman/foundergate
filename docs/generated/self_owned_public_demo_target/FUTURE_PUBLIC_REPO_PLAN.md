# Future Public Repo Plan (not executed in this run)

This demo target is *prepared* to become a public GitHub repo later, but **nothing is published in this run** (no external action authorized).

## When the founder decides to publish (a founder gate)
1. Review the code once more for anything sensitive (there is none by design).
2. Create a NEW public repo under the founder's own account (e.g. `foundergate-demo-tasks`) — separate from the private product repo.
3. Push ONLY the `demo/self_owned_public_demo_target/` contents as the repo root, with the MIT license and README already included.
4. Add a couple of small GitHub issues drawn from DEMO_OBJECTIVES.md so a live Safety Check has real, public issues to target.
5. Use it as the standing demo target for FounderGate walkthroughs and (later) design-partner outreach — "here's a public repo you can watch me run a governed check on."

## Guardrails
- Publishing is the founder's explicit decision — this run does not do it.
- Keep it clearly labelled a **demo fixture**, not a product.
- Never put anything real or sensitive in it.
- A self-owned public demo repo does not replace a real design partner; it lowers the barrier to showing one.
