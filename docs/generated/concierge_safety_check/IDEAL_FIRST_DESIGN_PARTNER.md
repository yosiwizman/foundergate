# Ideal FIRST Design Partner

The very first one should be the **lowest-risk, highest-trust** option:
1. **Someone you already know** who builds software and trusts you enough to give candid feedback.
2. Has a **public repo they don't mind being a guinea pig** (a side project, an OSS tool, a demo app).
3. **Low stakes:** the objective is a small, bounded change where an honest "insufficient" is totally fine.
4. **Fast feedback loop:** can hop on a 20-minute call this week.
5. **Not a paying-customer expectation yet** — the first run is about learning + a reference, not revenue.

**Why start here:** the first run's job is to prove the *process and the evidence note are useful and honest to a real human* — with zero pressure and zero risk. Revenue and scale come later, only after the honest signal is real.
